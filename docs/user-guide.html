User Guide

Getting the most out of DailyBot GUI

A walkthrough of every tab, what each setting actually does, and what to do when the portal asks for a login code. Written for the control panel exactly as it runs today.

Part one

Getting it installed

One-time setup on a new computer. After this, day-to-day use is just double-clicking one file.

  1. Download and extract the folder.

    Get the ZIP from GitHub (the green Code button → Download ZIP), then extract it somewhere permanent — Documents or Desktop, not Downloads, so it doesn't get cleaned up later.

  2. Double-click Setup.bat.

    It'll ask to run as administrator — allow it. It checks for Node.js and installs it automatically if missing (first via winget, falling back to a direct download if winget can't reach its source — either way, no action needed from you), installs the app's dependencies, downloads the browser engine it automates with, and asks for your portal login (or you can skip that and add it later from the Settings tab).

  3. Wait for "Setup complete!"

    This step can take several minutes the first time — it's downloading real components (Node.js itself, the browser engine), not just copying files. A slow or unstable connection will just make it take longer, not fail.

  4. Double-click Run DailyBot GUI.bat.

    A terminal window opens and starts the local server, then your browser opens automatically to the control panel at http://localhost:4287.

Keep this open Leave that terminal window running in the background while you use DailyBot. Closing it stops everything. Closing just the browser tab is fine — reopen http://localhost:4287 any time the terminal is still running.

Settings tab

Your login and every timing/behavior knob DailyBot uses. Saved only to this computer's local .env file — nothing here is sent anywhere except the portal itself.

Login

  • Email / Password — the same credentials you'd use to sign into the portal by hand. A ✓ Saved badge next to Password confirms one's on file — the field itself always clears after saving, so this badge is the only way to tell "saved" from "empty" at a glance. Type a new password to replace it, or leave it blank to keep the one you already saved.

Advanced → Location

  • Only needed if the portal asks for a location when logging a visit. Set your usual default here — Latitude and Longitude, side by side. Drop a pin on Google Maps, right-click it, and the numbers shown are ready to paste in.
  • Any single entry can override this — see Daily Entries below.

Advanced (.env) Settings

The defaults work well for almost everyone. Here's what each one actually controls:

HeadlessFalse shows the browser window while it runs — keep it this way until you're confident logins are reliably reusing a saved session. True hides the window, but if a login code is ever needed, there'd be nothing on screen to type it into. Slow motionAdds a small delay before every click/type, useful only if you want to visually follow along with what it's doing. Page navigation timeoutHow long to wait for a page to load. Floored at 20 seconds no matter what's entered. Action timeoutHow long to wait for a click target or field to appear before giving up on that step. Login-code waitHow long the browser waits for a human to type in an OTP. Floored at 45 seconds — enough time to check a phone. Retry attempts / delayHow many times, and how long to wait between tries, if a step fails and can safely be redone. Days before too oldMatches the portal's own edit-window rule (2 days, by default). Only change this if that rule itself changes on the portal. Log detail levelHow much detail gets written to the logs/ folder. Needs a restart of DailyBot GUI to take effect — everything else here applies on the very next run.

Daily Entries tab

Where you tell DailyBot what to submit — no more opening the Excel file by hand.

Add an entry

Fill in date, partner (the only required field), calls, meetings, blockers, tomorrow's priorities, and notes. For Location for this visit, there are three choices:

  • Use the default location — whatever's set in Settings. This is right for most entries.
  • Custom coordinates — type a one-off latitude/longitude for just this visit.
  • A saved location — pick a place you've saved before (see below) instead of retyping coordinates every time.

Saved Locations

Save a place once — a name plus coordinates — and it shows up in the dropdown above from then on. Useful for partners you visit repeatedly.

Pending entries

Shows exactly what the next run will submit. A row disappears automatically the moment it's confirmed submitted — nothing is ever double-submitted, even if a run crashes partway through and gets retried later.

About future-dated entries The portal itself won't accept a log for a date that hasn't arrived yet — DailyBot detects this automatically and skips those rows for now rather than wasting a run on something guaranteed to fail. They're not lost: the row stays in Pending entries and gets picked up on its own once that date actually arrives.

Run & Reports tab

Where you actually submit today's entries, and look back at what happened on past runs.

  • Run Now — opens a real browser window and does the actual submitting. Most days, nothing needs your attention.
  • Progress — a live log of exactly what's happening, streamed in as it runs.
  • Reports — every past run leaves a report here you can open — a full summary of what succeeded and what didn't.
  • A status line above Progress shows whether you're currently signed in and, if so, until when — see the next section.
If a login code appears Type it into that browser window, not the control panel page. DailyBot can't read or generate the code itself — it's sent to your phone or email, and it just waits for a human to enter it.

Scheduler tab

Runs DailyBot by itself at a set time, instead of clicking Run Now every day.

  • Turn it On, pick a time of day and which days (defaults to 08:00, Monday–Saturday). An Advanced raw cron field underneath covers anything the simple picker can't express.
  • The status line tells you the next scheduled run in plain terms, e.g. "Scheduler is on — next run: Mon 8:00 AM."
Two real limits This computer needs to be on (not asleep) and DailyBot GUI needs to still be running at the scheduled time. And if a login code happens to be needed that day, someone still needs to be there to type it in — same as running it manually.

Sessions & the login code

Why you're not asked for a code every single day, and how to see exactly when that changes.

After a successful login, DailyBot saves the session it was given. Every run checks that saved session first — if it's still good, it skips the login form entirely and no code is needed. You're only asked again once the portal's own session actually runs out, which is decided by the portal, not by DailyBot.

The Run & Reports tab shows this plainly, reading the real expiry the portal set:

●  Signed in — session good until Tue, Aug 4 2026, 8:15 AM
●  Session expired Fri, Jul 31 2026 — the next run will need the login code
●  No saved session yet — the next run will need the login code

Keep Headless off for scheduled runs specifically — on the days a code genuinely is needed, that just means someone glances at the screen and types 6 digits, instead of a run silently failing because nobody could see the prompt.

Software updates

A "Software Update" card lives at the bottom of the Settings tab.

  • Shows the version currently installed.
  • Check for Update fetches the latest version, keeping your login, entries, and saved locations exactly as they are — nothing personal is ever touched.
  • Progress streams live in a log box right there on the page, ending in one of a few outcomes: updated in place (just restart Run DailyBot GUI.bat), a fresh copy placed in a sibling folder for you to switch to, or — on a computer without Node.js yet — the files being ready plus instructions to run Setup.bat once more.
If it blocks If any of the app's own files have been hand-edited on this computer, the update stops and tells you so rather than overwriting your changes silently. That's a safeguard, not a bug — undo the edit (or ask whoever maintains this for you) and try again.

There's also a Update.bat file in the folder that does the same thing from outside the browser, useful if the control panel itself won't start for some reason.

Setting up another rep on their own computer

Each install is independent — its own login, its own entries, its own reports.

Copy the whole DailyBot-GUI folder to their computer and run Setup.bat there — it asks for their login, separately. Don't copy these folders between computers, since they're specific to one person and one machine:

.envcontains a saved password — each person enters their own via Setup.bat or the Settings tab. sessions/one person's saved login — reusing it elsewhere won't work and isn't meant to. node_modules/reinstalled fresh on each machine by Setup.bat — no need to copy it at all.

If something goes wrong

  • Check the Progress panel on the Run tab first — the error message usually says exactly what happened.
  • Open the newest entry in Reports for a full summary of what succeeded and what didn't.
  • The screenshots/ folder has a picture automatically saved at the exact moment anything failed.
  • The logs/ folder has the full detailed history if you need to dig deeper than the report shows.

Quick answers

Do I need to enter the login code every day?No — only when the saved session actually expires. See Sessions & the login code.
Can I close the browser tab?Yes. Just don't close the terminal window from Run DailyBot GUI.bat — that's what actually stops DailyBot.
What if I add an entry for tomorrow by mistake?Nothing to fix — DailyBot detects future-dated entries and skips them automatically until that date arrives.
How do I move this to a new laptop?Copy the whole folder over, run Setup.bat, then sign in fresh. See Setting up another rep.
Where do I get updates?The Check for Update button in Settings, or double-click Update.bat.
The Scheduler is on but nothing happened.Check the computer was on and DailyBot GUI was actually running at that time — both are required.
